Lesson 07 · Method

Show it once.
Then let it repeat.

A coding agent did most of the file editing, under fixed rules. It learns from an example, proposes before it acts, checks its own work, and leaves the final look to a person.

with Elizabeth Cecilia. Delegate the repetition, keep the judgement.

01

Three copies, three rules

The real projectPlain-text project files. The only thing the agent edits, and never used for experiments.
The seed projectA small example. A new setting is made here by hand in Power BI Desktop, so the agent can read exactly how Desktop stores it.
The frozen exportA published single-file snapshot. The agent never touches it.

Power BI's file format isn't fully documented, so the agent never guesses how a setting is written. It copies what Desktop itself wrote.

04

What it gets wrong, and the guard for each

RiskWhat happened, or couldGuard
Checks too looseA check confirmed a subtitle named a measure, not that it existed. Five broken cards passed.A check that every field the report names exists
Guessing a formatWriting a setting the way it "should" look, not the way Desktop writes itSeed first
Scope creepTidying files it wasn't asked to touchIt lists every file rewritten; anything unexpected is rejected
Confident, wrong countsA review said 22 relationships where there were 19A second, file-based inventory before anything is built on the numbers
No eyesA build passes every check and still looks wrongA person checks in Desktop before every save

The agent here is Claude Code, run in its Manual permission mode. Every change starts in plan mode, which blocks edits until the plan is approved, and each proposal is reviewed before approval. Commits need an explicit go-ahead.

05

The rule, in one breath

The agent does the repetitive precision work; the person keeps judgement and sign-off.

Show it once in the seed, let it propose, approve, let it build and validate, check with your own eyes, then commit. Every mistake it makes becomes a new rule or a new check.
